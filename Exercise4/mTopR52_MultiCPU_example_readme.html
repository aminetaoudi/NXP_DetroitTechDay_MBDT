Multicore Execution on ARM Cortex-R52

Open Example

The mTopR52_MultiCPU.mdl example shows how to use Concurrent Execution to run a Multicore application on ARM Cortex-R52 cores.

This model illustrates the explicit partitioning functionality in Simulink that allows running different Simulink models on different cores. In this case the R52 Core 0 Cluster 0 core is the boot core that will start the R52 Core 1 Cluster 0 and R52 Core 2 Cluster 0 remote cores. The R52 Core 2 is sending the input data to the R52 Core 1, where the data is used and then sent to validation to the R52 Core 0. The results of the computations is then validated on the R52 Core 0 and acknowledge messages are sent to the terminal using UART.

Note: for more information about Concurrent Execution in Simulink, please visit MathWorks website, Concepts in multicore programming, Setup partitions in explicit partitioning.

Note: the initialization settings for the components used in this example represent just a default EB Tresos available configuration. Users can change the configuration of the application to fit special requirements.

Toolchain Supported

  • S32 Design Studio v3.5.13

Required Hardware

  • Personal Computer

  • S32Z2xx/S32E2xx

  • 12V Power Supply

  • Micro USB cable

  • S32 Debugger probe

Prepare the Demo

  • Open the model and select the processor package. This model is configured for the S32E2xx-bga975 hardware package. If you would like to change the processor package, please follow the steps described in the Customization Options section.

  • Connect the S32 Debugger probe to the J129 JTAG pin connector on the EVB.

  • UART default configuration is using the LINFLEXD instance 9 which is also used for serial boot on S32E27X-DC4 EVB. Disable the BootROM to be able to use the serial.

  • Build and Download the program on the target processor. To build the multicore application, go to Model Settings -> Hardware Implementation -> Target hardware resources -> Groups -> Multicore and check Enable multicore execution then press the Build Selected Nodes button.

Running the Demo

  • Open a terminal (e.g: Putty) and configure it with the following information:

  • UART config.Settings
    Baud rate115200
    Data bits8
    Stop bits1
    ParityNone
    Flow ControlNone

  • COM port: Look it up inside Device Manager, under the Ports tab.

  • See the messages in the terminal. A correct run of the program will toggle the RED LED on the board.
